# Swarm — разработка

Electron, node-pty, xterm.js. Внешних сервисов нет.

```bash
npm install       # зависимости и node-pty под ABI Electron
npm start
npm test          # чистый Node, без Electron
```

## Модули

| Файл | Что делает |
|------|-----------|
| `main.js` | Electron main: pty-сессии, детект статуса, IPC |
| `preload.js` | Мост `window.swarm` между рендером и main |
| `git.js` | git-пломбинг для нижнего бара |
| `screen.js` | Разбор снимка экрана: строка вопроса и тип запроса |
| `detector.js` | Машина статусов: экранный детект, замок «ждёт», арбитраж с хуками |
| `osc.js` | Парсер невидимых маркеров хуков из потока pty |
| `hook-config.js`, `hooks/swarm-signal.mjs` | Конфиг и скрипт хуков Claude (opt-in) |
| `transcript.js` | Разбор журнала сессии: чем занят агент и текст вопроса |
| `ask-phrases.js` | Фразы конца хода: зовёт / ждёт фоновую задачу / закончил |
| `unread.js` | «Этот ответ человек ещё не видел»: пометка держит перезапуск, пока он не прочитает |
| `night.js` | Ночной режим: правило агенту, толчки, вопрос про порог фазы, итог после задачи |
| `agent-rules.js` | Правило для агента из тех же фраз: строка запуска и блок для `CLAUDE.md` |
| `launch-line.js` | Строка запуска вкладки: длинные значения через окружение, `clear` перед командой |
| `telegram.js` | Протокол моста: long polling, разбор апдейтов, маршрутизация |
| `voice.js` | Голос в текст: WAV, поиск whisper.cpp, разбор вывода |
| `swarm-statusline.js` | Строка статуса Клода: отдаёт нам контекст и окна подписки |
| `updater.js`, `updater-core.js` | Автообновление: манифест, докачка, установка нового кода |
| `bootstrap.js`, `boot-core.js` | Точка входа: чей код запускать — бандла или обновления |
| `renderer/` | UI: вкладки, терминалы, раскладки, покраска статусов |
| `scripts/release.mjs` | Скрипт релиза |

Логика, которую можно проверить без Electron, живёт в отдельных файлах чистым Node — отсюда и тесты без запуска приложения. Планы и дизайн-документы по крупным изменениям лежат в `docs/superpowers/`.

## Статус агента

Собирается из трёх источников по старшинству: хук, журнал сессии, экран.

- **Хуки** включаются в «Настройки → Запуск» и только для вкладок, запущенных приложением; глобальный `~/.claude/settings.json` не меняется. Это единственный канал, который видит диалоги: просит разрешение, задал структурный вопрос.
- **Журнал сессии** (`~/.claude/projects/**.jsonl`) даёт «работает / думает / конец хода» и точный текст вопроса. Вкладка привязана к своему файлу через `--session-id`, который задаёт само приложение.
- **Экран** остаётся подстраховкой: диалог разрешения виден только там, и там же работает детект для вкладок, где `claude` запущен не приложением.

## Чужие лончеры

Команда запуска вкладки задаётся пользователем, поэтому в ней может оказаться не Клод. Всё клодовское гейтится одним предикатом — `resume.supports(launcherOf(cmd))` (`renderer/resume.js:24`, стем команды: `claude`, `cld`, `claude-*`). Под этим гейтом живут `--settings` со строкой статуса и хуками, `--append-system-prompt`, `--permission-mode`, `--session-id` и построение `--resume` при восстановлении. Причина именно такая: неизвестный флаг Claude Code не проглатывает молча, а отказывается стартовать, так что для чужой команды лучше не добавить ничего.

Эти флаги приложение не запускает напрямую, а **печатает в оболочку вкладки**, поэтому оболочка их отражает — и первым, что человек видит в новой вкладке, оказывается наша служебная строка. Правило-подсказка одно тянет полтысячи символов. Поэтому длинные значения уезжают в **окружение** самой оболочки (`--append-system-prompt "$SWARM_ASK_RULE"`), а перед командой идёт `clear`, который стирает и её саму: `launch-line.js`. Синтаксис подстановки берётся только для оболочек, которые мы знаем наверняка; для незнакомой (`nu`, `xonsh`) значение по-прежнему пишется прямо в строку — нераскрытая `$SWARM_ASK_RULE` уехала бы Клоду как системный промпт, а нераскрытый путь к настройкам и вовсе не дал бы ему стартовать.

Отдельный случай — **обёртка вокруг Клода**: `alias claude-my='CLAUDE_CONFIG_DIR=… command claude'`, то есть другой аккаунт. Шелл разворачивает алиас до `exec`, поэтому в `ps` от него остаётся обычный `claude`, и наблюдатель за процессами норовит переписать вкладке лончер на менее точный — а с ним уезжают и аккаунт, и `--settings` со строкой статуса (без неё во вкладке нет ни полоски контекста, ни расхода лимитов). Гасится с двух сторон: свой собственный запуск приложение у `ps` не переспрашивает (`launchAt`/`launchPid` в `main.js scanTabProcesses`), а набранный руками алиас защищает `isAliasExpansion` (`renderer/launch-word.js`) — «запомненное имя начинается с увиденного» значит разворачивание, а не смену агента. Там же и разбор строки на запуск: флаг со значением отдельным словом (`--permission-mode auto`) тоже считается запуском, иначе вкладка не привязывалась к алиасу.

Дальше вниз по цепочке чужой лончер теряет и журнал (чужой агент не пишет `*.jsonl` вовсе — искать нечего), и опознание диалогов (`PERMISSION_RE` в `screen.js` ловит формулировки Клода). Остаётся экранный детект активности по `lastDataAt`. Обёртка вокруг Клода — не этот случай: журнал у неё есть, просто в другом конфиге, и приложение его находит (`configRoots` в `main.js`, все папки вида `~/.claude*`; точный адрес называет хук). Список того, что от этого ломается для пользователя, — в разделе «Другие агенты, кроме Клода» в `README.md`; если гейт меняется, править надо оба места.

## Сборка

Приложение нативное, поэтому каждая ОС собирается на своей платформе:

- macOS: `npm run dist` даёт `.dmg` под arm64. Подпись ad-hoc.
- Windows: `.exe` собирает CI по тегу либо `npm run dist:win` на Windows-машине.
- Поставить себе то, что сейчас в дереве: `npm run install-app` — сборка без `.dmg` и копирование в «Программы» (`SWARM_DEST` переопределяет папку). Карантина у собранного локально нет, поэтому Gatekeeper молчит.

Для пользователей есть третий путь — `scripts/install.sh`, установка одной командой из релиза. Он тоже обходит карантин, но по другой причине: карантин вешает скачавшее приложение, а `curl` этого не делает.

## Релиз

```bash
gh auth login                 # один раз, нужны scope repo и workflow
npm run release -- patch      # или minor / major
```

Скрипт гоняет тесты, поднимает версию, дописывает `CHANGELOG.md`, обновляет блок ссылок в `README.md`, коммитит с тегом, собирает `.dmg`, пушит и создаёт релиз черновиком с `.dmg`, `app.asar` и `manifest.json`.

Пуш тега запускает CI: тот собирает Windows `.exe`, доливает в тот же релиз и снимает черновик. Порядок важен: автообновление ходит за `releases/latest/download/manifest.json`, а черновики в `latest` не попадают, поэтому до сборки `.exe` новой версии для обновлялки не существует и никто не попадёт в окно, где манифест обещает установщик, которого ещё нет.

Токены в окружении не нужны: релизы публичные, `gh` авторизуется сам.

## Установщик в npm

`npm/` — отдельный пакет `claude-swarm` размером в три килобайта. Это установщик, а не приложение: внутри лежит тот же `scripts/install.sh` (кладётся при публикации, см. `prepack`), а `bin/cli.mjs` только запускает его.

**Версия пакета намеренно не связана с версией Swarm.** Установщик берёт манифест последнего релиза в момент запуска, поэтому на каждый релиз приложения переиздавать его не нужно — и в скрипт релиза он поэтому не заведён.

Переиздавать нужно ровно тогда, когда поменялся `scripts/install.sh`. Иначе `npx claude-swarm` будет ставить старым скриптом, а `curl` из README — новым, и они разъедутся:

```bash
cd npm && npm version patch     # версию поднять и закоммитить
git push
gh workflow run publish-npm.yml # публикует CI
```

Публикует `.github/workflows/publish-npm.yml` вручную, по кнопке. **Токенов для этого не нужно.** Реестр доверяет самому workflow (npm Trusted Publishing): гитхаб выдаёт заданию короткоживущий OIDC-токен, npm меняет его на право опубликовать именно этот пакет и именно из этого файла. Долгоживущий гранулярный токен, который лежал в ящике стола и однажды протух бы посреди срочной правки установщика, из схемы исчезает — красть и продлевать нечего.

Побочная выгода: у публикаций из CI реестр сам проставляет **происхождение** (provenance) — на странице пакета появляется ссылка на конкретный прогон, из которого собран этот тарбол.

Настройка на стороне npm — один раз, руками, кода не касается. На npmjs.com → пакет `claude-swarm` → **Settings** → **Trusted Publisher** → **GitHub Actions**, и четыре поля:

| Поле | Значение |
|------|----------|
| Organization or user | `raul-cortez` |
| Repository | `claude-swarm` |
| Workflow filename | `publish-npm.yml` |
| Environment | пусто |

Все поля сверяются дословно и с учётом регистра. Из этого следуют две мины: **переименование workflow-файла ломает публикацию** (чинится только на сайте, в репозитории править нечего), и `repository.url` в `npm/package.json` должен указывать ровно на этот же гитхабовый адрес — иначе не подпишется происхождение.

Настроить доверие можно только существующему пакету, поэтому первая публикация в любом случае была ручной, с токеном. Она уже состоялась; токен после этого можно отозвать, а в аккаунте включить **Require two-factor authentication and disallow tokens** — тогда единственный путь к публикации остаётся через CI.

## Обновление: установленное приложение не меняется

Точка входа — `bootstrap.js`. Он выбирает, чей код запускать: тот, что лежит в бандле, или обновлённый `<userData>/payload/<версия>.asar`, на который показывает `current.json`. Обновление скачивает этот файл и переставляет указатель; бандл после установки не трогается никогда.

Так сделано не из любви к развязкам. Подпись macOS покрывает всё содержимое бандла, поэтому прежняя подмена `app.asar` её ломала и требовала переподписи уже на машине пользователя — а с каждой переподписью менялся отпечаток приложения, то есть для системы это было новое приложение, и выданные разрешения на папки сбрасывались. На Windows та же подмена упиралась в файл, занятый работающим приложением, и требовала хелпера на PowerShell с обходом job object. Сейчас ни того, ни другого в коде нет, а перезапуск после обновления — обычный `app.relaunch()`.

Что из этого следует держать в голове:

- **Запасной путь — всегда бандл.** Любая ошибка загрузчика, битый файл, непрочитанный указатель — приложение поднимется на своей исходной версии. Сломать установку обновлением нельзя.
- **Версия, которая три раза подряд не дожила до рабочего состояния, бракуется** (`ATTEMPT_LIMIT` в `boot-core.js`): файл уезжает в `.broken`, указатель снимается. Не с одной попытки — вторая копия сворма закрывается сама и не успевает отметиться удачной.
- **Версия приложения берётся из выполняемого кода** (`updater.runningVersion()`), а не из `app.getVersion()`: последний читает `package.json` бандла и после обновления показывал бы версию, с которой приложение когда-то поставили.
- **Нативные модули остаются в бандле** и грузятся от `process.resourcesPath` (`pty-loader.js`). Поэтому `scripts/strip-asar-natives.mjs` вырезает `node-pty` из ассета обновления — всё остальное там лежит внутри архива и читается прямо оттуда, включая хуки и строку статуса.
- **Полный установщик всё ещё нужен**, когда меняется `runtimeId` (версия Electron или node-pty): такое обновление одним файлом не доедет, и это ровно та развилка, что была раньше.
