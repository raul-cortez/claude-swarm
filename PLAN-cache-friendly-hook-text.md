# План: убрать session id из текста хука — он рвёт промпт-кэш Anthropic на каждой вкладке

**Кто просил:** владелец, 2026-08-28, по итогам расследования в соседнем проекте (fastio) —
почему 5ч-лимит подписки улетает быстрее, чем раньше.
**Где менять:** `hooks/swarm-signal.mjs`.
**Не трогать:** `main.js`, детект статуса, реальные имена файлов `.swarm-restart-*.json` /
`.swarm-digest-*.json` на диске — фикс только про ТЕКСТ, который видит модель, файлы остаются как есть.

---

## Что подтверждено (замер в fastio, другая сессия того же дня)

У Anthropic prompt-кэш работает по точному совпадению префикса: как только в тексте, который
харнесс кладёт в начало разговора, встречается первый отличающийся байт, ВСЁ, что идёт дальше в
том же кэш-сегменте, пишется заново по полной цене (`cache_creation`, вес ×1.25) вместо дешёвого
переиспользования (`cache_read`, вес ×0.1 — в 12.5 раза дешевле).

Разобрал `usage` из транскриптов сегодняшних сессий (`~/.claude-my/projects/.../*.jsonl`, поле
`"usage":{...}` в первом ответе ассистента). Один и тот же общий объём контекста (~65–80k токенов)
даёт два разных исхода:
- «тёплый старт»: `cache_creation ~40k` + `cache_read ~26–38k` — половина переиспользована
- «холодный старт»: `cache_creation ~80k`, `cache_read 0` — оплачено всё заново

Сравнил байты SessionStart-инъекции двух сессий, стартовавших почти одновременно. Всё совпало
(индекс codemap, дайджест «хвосты сессий», текст skill'а `superpowers:using-superpowers` — один в
один), КРОМЕ ровно одного блока: инструкции про самоперезапуск/дайджест, где буквально написано
имя файла с UUID сессии внутри, например:

```
...положи в свою рабочую папку файл
.swarm-restart-2bfd283e-afd6-46b4-a8d6-e83cc68c476c.json с одним JSON-объектом...
```

У каждой вкладки свой UUID → этот блок ГАРАНТИРОВАННО разный на каждой сессии → именно на нём
рвётся кэш, и всё, что харнесс кладёт после него (список скиллов ~7.9k, список агентов ~3.7k,
MCP-инструкции, список отложенных тулов) переписывается заново каждый раз, даже когда всё
остальное (CLAUDE.md, память, codemap, сам список тулов) не изменилось ни на байт.

## Откуда в коде

`selfRestartNote(file)` (строка ~303) и `digestNote(file)` (строка ~348) в
`hooks/swarm-signal.mjs` принимают УЖЕ РАЗРЕШЁННОЕ имя файла (`restartFileFor(sid)` /
`digestFileFor(sid)`, строки ~326 и ~338) и интерполируют его прямо в текст, который харнесс
кладёт в `additionalContext` на `SessionStart` (вызовы — строки ~677 и ~682).

Есть и вторая, более частая утечка: `digestMissingNudge(file)` (строка ~344) — короткое
напоминание, которое печатается на КАЖДОМ ходе (`UserPromptSubmit`, не только на старте), пока
агент не написал дайджест первый раз (строка ~665-670). Оно тоже интерполирует резолвнутое имя
файла и тоже рвёт кэш — но уже НЕ на старте сессии, а на каждом ходе, пока файл не появится.

## Почему можно просто убрать sid из текста

У Claude Code уже есть переменная окружения, которая говорит агенту его собственный id сессии,
и она совпадает с тем `sid`, который хук получает из payload:

```
$ env | grep CLAUDE_CODE_SESSION_ID
CLAUDE_CODE_SESSION_ID=2bfd283e-afd6-46b4-a8d6-e83cc68c476c
```

Значит хуку не обязательно печатать РЕЗОЛВНУТОЕ имя файла в тексте — можно напечатать один и тот
же для всех сессий шаблон и научить агента подставить своё значение самому перед записью.

## Что менять

1. **`selfRestartNote`** — сейчас принимает готовое имя файла и вставляет его в текст. Поменять
   на печать константного шаблона: `.swarm-restart-$CLAUDE_CODE_SESSION_ID.json`, плюс одна
   короткая фраза, что это переменная окружения его собственной сессии (агент и так умеет читать
   переменные через `Bash`). Текст должен стать БАЙТ-В-БАЙТ одинаковым независимо от `file`.

2. **`digestNote`** — то же самое, шаблон `.swarm-digest-$CLAUDE_CODE_SESSION_ID.json`.

3. **`digestMissingNudge`** — то же самое (это менее приоритетно по объёму, но чинится тем же
   диффом за секунды, и не чинить — оставлять примерно тот же баг на каждом ходе).

4. **`restartFileFor(sid)` / `digestFileFor(sid)` — НЕ ТРОГАТЬ.** Они по-прежнему нужны с
   РЕАЛЬНЫМ `sid`: `main.js` детектит файл на диске по резолвнутому имени, `digestWritten()`
   делает `existsSync` по резолвнутому имени. Меняется только то, что печатается модели, не то,
   что реально читается/пишется с диска.

5. Проверить, не берёт ли что-то ещё (например, `main.js`, `restart.js`) текст `selfRestartNote`/
   `digestNote` и не ждёт ли там резолвнутого имени — по коду сейчас похоже, что нет (это чисто
   текст для модели), но стоит перепроверить грепом перед правкой:
   `grep -rn "selfRestartNote\|digestNote\|digestMissingNudge" --include=*.js .`

## Тесты (`test/hook.test.js`)

- Строка ~677: `assert.match(out.hookSpecificOutput.additionalContext, /\.swarm-restart-sid-9\.json/)`
  — это проверяло, что текст содержит РЕЗОЛВНУТОЕ имя. После фикса должно быть наоборот: текст
  содержит буквально `$CLAUDE_CODE_SESSION_ID`, а НЕ `sid-9`. Переписать assert.
- Добавить новый тест: сгенерировать `additionalContext` для ДВУХ РАЗНЫХ `sid` (например `sid-9` и
  `sid-42`) и проверить, что итоговые строки **идентичны** (`assert.strictEqual`) — это и есть
  контракт, который чинит кэш-баг, стоит закрепить явным тестом, а не только гадать по старому.
- Строки ~646 и ~691 (`assert.strictEqual(H.restartFileFor(sid), restart.answerName(sid))` и
  аналог для digest) — НЕ трогать, они про реальное имя файла, не про текст.
- Строки ~718-729 (tmpdir-тест на `digestMissingNudge`) — проверить, что `existsSync`-логика
  (`digestWritten`) по-прежнему матчит РЕАЛЬНЫЙ файл на диске (созданный с резолвнутым именем), а
  вот сам текст напоминания в этом тесте теперь должен проверяться на шаблон, а не на `sid`.

## Проверить перед коммитом

- `$CLAUDE_CODE_SESSION_ID` доступен агенту во всех сценариях, не только в обычном старте —
  проверить на resume/compact, и отдельно на Windows (там свои соглашения про env, см.
  `WINDOWS.md`) — не сломать инструкцию для пользователей на Windows.
- В тексте явно попросить агента СНАЧАЛА подставить значение переменной, ПОТОМ собирать имя
  файла — `Write`-тул не разворачивает `$VAR` сам, разворачивание — либо через `Bash`
  (`cat > .swarm-restart-$CLAUDE_CODE_SESSION_ID.json <<'EOF' ... EOF`), либо агент сам читает
  `echo $CLAUDE_CODE_SESSION_ID` и подставляет вручную. Стоит явно сказать это в тексте, а не
  полагаться, что агент догадается.
- После фикса убедиться, что перед этим блоком в потоке инъекций (codemap → episodic-sync-хук →
  дайджест «хвосты сессий» → этот блок → …) больше нет других по-сессийных различий — иначе кэш
  всё равно порвётся, просто чуть раньше. Судя по разбору в fastio, всё, что стоит ДО этого блока,
  сегодня было идентично между сессиями — но стоит перепроверить эмпирически после фикса (см. ниже).

## Как проверить эффект после фикса

Поднять две новые вкладки подряд (не более пары минут одна за другой, чтобы попасть в TTL кэша),
сравнить первый `usage` в их транскриптах:

```bash
grep -m1 -o '"usage":{[^}]*}' ~/.claude-my/projects/-Users-evgeniy-WebstormProjects-fastio/<второй-uuid>.jsonl
```

До фикса вторая вкладка обычно давала `cache_creation ~40k` / `cache_read ~26-38k` в лучшем случае
(SessionStart-блок с sid уже рвал кэш дальше по потоку). После фикса ожидается, что `cache_read`
вырастет (переиспользуется и то, что раньше было в «вечно свежем хвосте» — списки скиллов/агентов),
а `cache_creation` упадёт. Если разницы нет — значит порвало кэш что-то ещё, искать по тому же
методу (диффать байты SessionStart-инъекции двух вкладок).

## Коммит

Отдельным логическим коммитом, `npm test` зелёный до коммита. В сообщении коммита явно упомянуть,
что это фикс промпт-кэша (не «косметика текста»), чтобы при следующем ревью не сократили обратно
до «покороче» — стабильность байтов текста здесь важнее лаконичности.
