## Этап 0. Две развилки — стендом, до кода

**0.1. Где лежат файлы.** Сейчас всё служебное лежит в папке вкладки, потому что запись вне
её Клод спрашивает отдельным разрешением. Для дайджеста это терпимо, для досье — нет: файл
живёт днями в чужом репозитории, и соседний агент с `git add -A` закоммитит его.
Проверить: `--settings` с `permissions.additionalDirectories: [<userData>/tabs]` плюс
`allow: Edit/Write(<userData>/tabs/**)` — пишет ли агент туда без вопроса в ручном режиме и в
auto. Сворм `--settings` уже подкладывает (строка статуса), но не всегда — при выключенной
своей строке статуса он его не добавляет; это придётся развести.
- Да → файлы в `<userData>/tabs/<tabKey>/`, репозиторий чистый.
- Нет → папка вкладки, `.swarm-dossier-<tabKey>.md` / `.swarm-work-<tabKey>.md`, и сворм
  дописывает `.swarm-*` в `.git/info/exclude` репозитория (локально, не коммитится).

**0.2. Что `--resume` делает с недоставленным.** После падения сворм предлагает поднять тот же
разговор. Стенд как вчерашний: набрать сообщение в занятого агента, убить, поднять `--resume`
— доставит ли Клод сам `enqueue` без `remove`. Нет → сворм отдаёт их сам (этап 4).

Итог этапа — две строки в этом плане и в памяти проекта.

## Этап 1. Чистый модуль `dossier.js`

UMD, как `digest.js`/`restart.js`, без ввода-вывода, весь на тестах (`test/dossier.test.js`).
Новый модуль — по-английски, как решено для проекта.

- `fileNames(tabKey)` → `{ dossier, work, inherit }`.
- `templates()` → тексты двух шаблонов из спеки.
- `undelivered(entries)` → сообщения с `queue-operation enqueue` без парного `remove`
  (по `content` и порядку; два одинаковых текста — тест).
- `tailAfter(entries, markUuid)` → сообщения человека и финальные тексты ответов агента после
  отметки, без инструментов и системных вставок; потолок по длине с обрезкой с головы.
- `humanCountAfter(entries, markUuid)` → для подталкивания.
- `workStale(workMtime, entries)` → был ли после правки файла работы ход с инструментами.
- `inheritText({ how, tail, undelivered, paths })` → файл наследства для новой сессии.
- `sweepPlan({ dirs, liveKeys, now })` → что в архив, что удалить (30 дней), что не трогать.

## Этап 2. Файлы и жизненный цикл (main.js)

- **Заведение.** Первая сессия вкладки при включённой функции → сворм кладёт оба шаблона, если
  файлов нет. Агент правит готовую форму, а не выдумывает свою.
- **Путь агенту.** `files[sid]` в `swarm-tgmode.json` получает `dossier` и `work` — тем же
  механизмом, что `restart`/`digest`. Путь от `tabKey`, не от sid: текст стабилен внутри
  вкладки между перезапусками, кэш не рвётся.
- **Отметка «разобрано до».** В такте дайджеста: mtime досье изменился → запомнить uuid
  последней записи лога. Хранить в `<tabKey>/state.json`, а не только в памяти: отметка должна
  пережить перезапуск самого сворма. Файл работы отметку не двигает.
- **Версии.** Изменилось досье → предыдущая версия в `history/`, последние 5.
- **Закрытие вкладки = архив.** Только на явное закрытие человеком (или бригадиром), НЕ в
  `child.onExit`: тот же onExit приходит при выходе из приложения, а такие вкладки потом
  восстанавливаются и досье им нужно.
- **Уборка на старте.** Папки без вкладки в восстановленном списке → архив; архив старше 30
  дней → удалить. По `sweepPlan`.
- **Новая задача в той же вкладке** — делает агент (заменяет бриф и план), версия старого
  остаётся в `history/`. Свормe тут ничего не нужно.

## Этап 3. Тексты агенту (hooks/swarm-signal.mjs)

- **На старте** — инструкция из спеки, за галочкой, после `digestIntro`. Подагенту не говорим.
- **Подталкивание** — `note` на UserPromptSubmit, когда `humanCountAfter ≥ 5`. Счёт делает
  main.js и кладёт в `files[sid].dossierLag`; хук только печатает. Гаснет на первой правке.
- **Пока файлы пусты** — короткое напоминание на ходе, как `digestMissingNudge`: бриф пишется
  с первых слов человека, а не через десять ходов.
- Тест на дубль имён файлов между хуком и `dossier.js`, как у дайджеста.

## Этап 4. Наследство новой сессии

- Перед перезапуском и при падении сворм запоминает лог уходящей сессии (`d.prevTranscript`):
  у новой будет свой файл, хвост берётся из старого.
- **Перезапуск по контексту / подъём без `--resume`** → `inherit`-файл: досье, работа, хвост
  после отметки, недоставленное. SessionStart новой сессии говорит прочитать его первым
  (текст «для новой сессии» из спеки). После прочтения — стереть, как сейчас записку.
- **Подъём через `--resume`** → разговор цел, хвост не нужен; недоставленное — по итогам 0.2.

## Этап 5. Перезапуск худеет

- `restart.js`: при включённом досье `handoff`/`text` необязательны; без них перезапуск
  разрешается.
- `restartGrant`: `workStale` → не отказ, а `retry` с просьбой «обнови файл работы» тем же
  путём, что сейчас просьба на пороге.
- `swarm-restart-guide.md` и `selfRestartNote`: пример JSON без `handoff`, гайд — «освежи
  файл работы, проверь Открытое, назови модель».
- Выключено досье → всё как сейчас, старый путь не трогаем.

## Этап 6. Настройка и вид

- Settings → Запуск: «Досье вкладки», по умолчанию включено. Выключено — честно «как
  раньше»: эстафета, без досье.
- Меню карточки: «Открыть досье» / «Открыть файл работы» — посмотреть, что вкладка помнит.

## Этап 7. Проверка

- Юниты на этапах 1–5.
- Живьём, на песочном проекте, не в рабочем свормe ([[local-payload-delivery]]):
  1. Дать бриф и два замечания (одно с «до:») → оба в досье, с метками.
  2. Перезапуск по контексту (порог занизить) → новая сессия знает правила И следующий шаг.
  3. Набрать сообщение в занятого агента, убить процесс → новая сессия отвечает на него.
  4. Закрыть вкладку молча → досье в архиве; перезапуск сворма → вкладки с досье живы.
- Релиз — только по слову.

## Порядок и объём

0 → 1 → 2 → 3 → 4 → 5 → 6 → 7. Этапы 1–3 уже дают пользу (досье ведётся), 4–5 — то, ради
чего всё. Объём на глаз: модуль ~300 строк с тестами, main.js ~250, хук ~80, гайд и
настройка — мелочь.
