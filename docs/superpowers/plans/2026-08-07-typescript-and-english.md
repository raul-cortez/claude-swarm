# TypeScript + английский: план работ

Дата: 2026-08-07. Статус: не начат.

Документ рабочий, внутренний — потому и на русском, как соседние планы в этой папке.
Правило про английский относится к коду, комментариям, публичным докам и коммитам.

## Зачем

Две задачи, которые выгодно делать одним проходом:

1. **Типы.** 14 700 строк своего кода без типов. Переименования и рефакторинг делаются
   грепом; при следующем крупном изменении это станет больно.
2. **Английский.** Проект метит на мировой рынок. Сейчас на русском: 3176 строк
   комментариев в коде (22%), 793 строки документации, интерфейс целиком, сообщения
   Telegram-бота, 32 из последних 40 коммитов.

Делать их раздельно — значит переписать каждый файл дважды и дважды затоптать `git blame`.

## Главное правило

**Любой файл, который тронули, выходит из-под руки на английском и со строками в словаре.**

Отдельного «этапа перевода» нет. Перевод едет вместе с рефакторингом, файл переписывается
один раз. Единственное исключение — документация: она ни от чего не зависит и делается сразу.

## Решения, уже принятые

- **Интерфейс — два языка (i18n).** Строки выносятся в словари, язык выбирается по системной
  локали, в настройках есть переключатель. Русский остаётся для себя, мир видит английский.
- **Документация — английская основная, `README.ru.md` рядом.**
- **`docs/superpowers/` не трогаем** — внутренняя кухня, не витрина.

## Что уже проверено

- **Переезд исходников в отдельную папку сборки безопасен.** `provisionNodeLauncher`
  (main.js:174) копирует `swarm-statusline.js` и `hooks/swarm-signal.mjs` из `__dirname`
  в userData при каждом старте, и в настройки Клода пишется путь к копии. Меняется только
  путь относительно `__dirname` — у существующих пользователей ничего не отвалится.
- **Оговорка:** `hooks/swarm-signal.mjs` запускается Node-ом напрямую и копируется под своим
  именем. Если мигрировать его на TS, компилировать надо в `.mjs` с тем же именем файла.
- **Renderer не использует модули.** Девять файлов подключены `<script src>` в `index.html`
  и общаются через глобальные переменные. Это блокирует TypeScript в renderer.
- **`ask-phrases.js` и `agent-rules.js` живут в двух мирах** — `require` из main и
  `<script src>` в renderer. Двойной режим придётся разруливать руками.

## Этап 0. Рельсы

Ничего не переезжает, только появляется инфраструктура.

- `tsconfig.json`, компиляция в отдельную папку выхода, `main` в package.json на неё же.
- Список `build.files` в package.json переключается на выход сборки.
- CI: проверка типов в `validate.yml`.
- **`test/lang.test.js`** — падает, если в файле из списка «уже переведённых» появилась
  кириллица. Список пополняется по мере работы. Это то, что не даст откатиться назад,
  когда через месяц рука сама напишет комментарий по-русски.
- **Каркас i18n:** модуль со словарями, доступный и main, и renderer (по образцу
  `ask-phrases.js`). Функция `t(key)`, плоские ключи. Выбор языка: системная локаль +
  настройка. Тест на полноту словарей — все ключи есть в обоих.
- Обкатать каркас на одном экране целиком (настройки), убедиться, что им удобно
  пользоваться, и только потом раскатывать.
- Договорённость о коммитах: Conventional Commits на английском.

Готово, когда: `npm test` зелёный, приложение запускается, один экран переключает язык.

## Этап 1. Документация

README, MANUAL, WINDOWS, DEVELOPMENT, CHANGELOG → английский. Русские версии остаются
как `*.ru.md` со взаимными ссылками.

**Не машинный перевод.** Доки написаны живым языком; дословный перегон даст канцелярит,
который на английском читается хуже среднего README. Переписывать заново английской
фразой, а не переводить русскую.

Готово, когда: английская версия — основная, ссылки на русскую работают.

## Этап 2. Renderer на модули

Самый рискованный этап: автотестов на живой UI нет, только на логику.

- `<script src>` → ES-модули.
- `renderer/renderer.js` (4098 строк) разбивается по темам.
- Решается двойной режим `ask-phrases.js` / `agent-rules.js`.
- Попутно: комментарии на английский, 176 UI-строк в словарь.

Делать мелкими коммитами, каждый — с запуском приложения и проверкой руками.

Готово, когда: приложение работает, `npm test` зелёный, в renderer нет глобальных скриптов.

## Этап 3. main.js

4622 строки → модули по ответственности: pty-сессии, IPC, меню, окно, настройки.
Тесты прикрывают больше, чем в renderer, риск ниже.

Попутно: комментарии на английский (1410 строк), 356 UI-строк (меню, диалоги) в словарь.

## Этап 4. TypeScript по слоям

Порядок: 24 маленьких модуля → main → renderer.

Маленькие модули идут почти механически: честный CommonJS с `module.exports`, чистые
функции, все покрыты тестами. Тесты остаются на JS.

В main и renderer TypeScript начнёт находить настоящие проблемы вида «здесь может прийти
`undefined`». Каждую разбирать по существу, не заглушать.

В renderer отдельно всплывёт DOM: `document.getElementById('x').value` → «может быть
`null`», и таких мест сотни.

## Этап 5. Хвосты

- `telegram.js` (816 строк, 235 русских): сообщения бота в словарь, язык бота — по настройке
  приложения.
- **Промпт агенту** в `telegram.js` («из Telegram — отвечай коротко, текстом на телефон»)
  велит отвечать по-русски. Это не строка интерфейса, а поведение — решать отдельно:
  вероятно, язык ответа агента должен идти за языком интерфейса.
- `voice.js`, `screen.js`, `transcript.js`, `detector.js`, `updater.js`,
  `swarm-statusline.js`, `hooks/swarm-signal.mjs`, `scripts/*.mjs` — по тому же правилу.

## Риски

| Риск | Что делаем |
|---|---|
| Ломается UI на этапе 2, тестов нет | Мелкие коммиты, ручная проверка каждого |
| `git blame` затаптывается переводом | Один проход на файл: рефакторинг + перевод вместе |
| Машинный перевод убивает качество текстов | Переписывать заново, не переводить дословно |
| Возврат русского в новый код | `test/lang.test.js` в CI |
| Словари расходятся | Тест на полноту ключей |
| `hooks/swarm-signal.mjs` при миграции на TS | Компилировать в `.mjs` под тем же именем |

## Порядок и независимость

Этап 1 (документация) независим — можно делать когда угодно, хоть первым.
Этап 0 нужен всем остальным. Этапы 2 и 3 независимы друг от друга.
Этап 4 требует 2 и 3. Этап 5 — в любой момент после 0.
