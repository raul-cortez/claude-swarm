## Сделано сверх этого файла (шаг 3, коммит после «Что дальше — шаг 3» ниже)

Найм по просьбе прораба: протокол + потолок бригады.

- `hire.js` — новый чистый модуль (UMD, как `digest.js`): `fileName(sid)` (`.swarm-hire-<sid>.json`),
  `clampCeiling` (1–20, умолчание 6), `parseRequest(raw)` — разбор `{"hire": [{name, prompt,
  model?}]}` с обрезкой длины и терпимостью к мусору в одной записи. Тесты — `test/hire.test.js`.
- `main.js`: `hireTick` (такт 5с) читает файл заявки прораба (`d.crew`), проверяет потолок
  (живые дети по `parentId`, не общий счётчик), открывает принятых через `app:createTab`
  (`parentId`/`name`/`model`/`hireTask` в payload), при упоре в потолок печатает прорабу одну
  строку сразу. `hireFireTick` печатает задачу в новую вкладку, как только `d.status === 'ready'`
  (тот же сигнал, что у `tgOnDone`) — с потолком ожидания 5 минут, иначе молча сдаётся (вкладка
  остаётся в бригаде пустой, прораб её видит). Обратная связь «кого открыл и как зовётся в
  списке агентов» — отдельной строкой прямо из `session:create`, как только известен
  `sessionKey`. Найм даёт вкладке мандат **безусловно** (`d0.auto` включает `!!opts.hireTask`) —
  без этого исполнитель встал бы на первом же вопросе и звал бы человека, а не прораба (вот
  этого «звать прораба, не человека» — маршрутизации вопросов — здесь ещё нет, это шаг 4).
  Потолок — настройка `settings:crew`/`CREW_MAX`, персист как у digest/restart.
- `renderer.js`: `onCreateTab` для найма не открывает пикер агента (нанимать некому на него
  отвечать) — наследует команду соседней вкладки папки или умолчание, применяет `model` через
  `RESTART_API.withModel`. Настройка «Потолок бригады» — range-поле в Settings → Запуск, без
  тумблера (роль прораба не выключается настройкой).
- `hooks/swarm-signal.mjs`: `crewNote` прорабу теперь называет протокол (путь файла, формат
  JSON, потолок) вместо «пока не говорим». `hireFileFor` — дубликат `hire.fileName`, `main()`
  прокидывает `tg.crew` в `outputFor`. Тесты парности и e2e — `test/hook.test.js`.
- `package.json`: `hire.js` в `build.files` (иначе упаковка ломается на `MODULE_NOT_FOUND`,
  ловит `test/package-files.test.js`), `test/hire.test.js` в `npm test`.
- `npm test` — весь набор зелёный (`hire.test.js` 14/14, `hook.test.js` 92/92, остальное как было).
- **Не проверено глазами** — живой найм (файл заявки → открывшаяся вкладка → напечатанная
  задача) не гонялся руками, только тестами модулей и e2e хука. Стоит проверить на живой
  бригаде при случае: пишет ли реальный Claude-прораб валидный JSON с первого раза, не путает
  ли `model` с чем-то другим.

## Что дальше — шаг 1 порядка работ

Родство вкладок + фильтр реестра + строки на старте сессии. Это закрывает исходную боль
(«каждый раз объяснять прорабу, какие вкладки его») почти без интерфейса, и делается до
всякого визуала.

1. **Родство.** У вкладки появляется родитель. Живёт там же, где мандат: в состоянии вкладки
   (`det` в `main.js`) и в `persistTabs` рендерера, чтобы переживало перезапуск приложения.
   Мандат (`auto`) — готовый образец, как это заводится и куда прокладывается.
2. **Фильтр реестра.** `peers.js` собирает `swarm-tabs.json` одним списком для всех
   (`peers.rows(det)` → `writeTabsMap`, `main.js:2991`). Нужен реестр **для конкретного
   читателя**: прораб видит свою бригаду и «свободных: N», ребёнок — только своего прораба,
   одиночка — всё как сейчас. Модуль чистый и покрыт `test/peers.test.js` — решение принимается
   там, тесты туда же.
3. **Строки на старте сессии.** `hooks/swarm-signal.mjs`: рядом с `peersNote` (строка 423)
   появляются формулировки для прораба и для ребёнка. Ребёнку — только механика («твой прораб —
   вкладка X, вопросы ему»): он обычная вкладка и правила процесса читает из `CLAUDE.md`
   проекта.

Дальше по спеке: карточка прораба и раскрытие → найм по просьбе → вопросы, закрытие бригады,
телега → настройка кнопок в углу карточки.
