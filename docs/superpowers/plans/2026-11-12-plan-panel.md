Вид и решения согласованы с человеком по кадрам. Макет: `2026-11-12-stand/scene-plan-mock.js`

## Что хочет человек

Если у вкладки появился план/чеклист (он живёт в досье, в разделе «## План» файла работы),
приложение это понимает и показывает справа вверху окна агента кнопку «План 3/6»; по ней справа
выезжает панель с деревом плана и галками, сужая терминал — как панель терминала (⌘J).

## Решения человека (не пересматривать)

1. Панель — **витрина, только чтение**. Галки ставит агент (пишет файл работы), человек не кликает.
   Значит: никакой записи из приложения в файл, никаких уведомлений агенту, никаких копий файла.
2. Вкладка без плана: кнопки нет — открыть панель нельзя. Панель открыта, перешли на вкладку без
   плана → **закрывается сама**, а вернулись на вкладку с планом → открывается снова (помним
   «человек хотел её открытой»). Надписи «плана нет» не делаем.
3. Кнопка **плавающая** (position:absolute) в правом верхнем углу `#stage-agents`, пилюля
   «значок План 3/6» (бейдж — верхние шаги: сделано/всего). Отдельной полосы над терминалом НЕТ.
   Дайджест обходит кнопку отступом справа (как раньше обходил плашку прораба). Нижняя панель
   (#statusbar) не трогается — там общее для приложения и гит.
4. Лейбл прораба уже убран (коммиты 5ae99f8, b1a06f4): «Прораб: <дайджест>» префиксом, без
   дайджеста — ничего.
5. Открыта панель → кнопка подсвечена акцентом. Панель на всю высоту справа от #stage-agents:
   заголовок «План» + «3 из 6», дерево (сделанное зачёркнуто и приглушено, `[>]` — янтарная
   подсветка, подшаги со сдвигом), внизу «Файл работы · обновлено …» (клик — открыть файл).
   Ширина тянется (как #term-split), запоминается.

## Что уже выяснено (проработка Opus-агента)

- Источник: файл работы вкладки (work.md в папке досье), раздел «## План» — дерево с отметками
  `[x]` сделано, `[ ]` нет, `[>]` мы здесь, подшаги вложены. Агенту при старте уже сказано, когда
  его писать (hooks/swarm-signal.mjs, dossierNote ≈ строка 600; шаблон раздела — dossier.js).
- «План есть» = в разделе «## План» не меньше 2 строк с `[ ]`/`[x]`/`[>]`. Больше ничего.
- НЕ делать: угадывать план по экрану терминала; брать внутренний список дел Claude Code (мелкие
  шаги внутри хода — панель мигала бы); просить агента дублировать план в другой файл.
- Приложение уже следит за досье (main.js dossierRefreshMark / dossierTick ≈ строка 6560) —
  файл работы читать тем же способом: изменилась mtime → перечитать и разобрать.
- Если без `[>]` — «где мы» считать по первому незакрытому шагу.
- Если агент ведёт план в СВОЁМ файле (PLAN.md в репозитории и т.п.), панель его не разбирает;
  первая версия показывает план только из файла работы.
- Ширина терминала: каждое изменение ширины заставляет Claude Code перерисовать экран — refit
  терминала только в конце перетаскивания/анимации, не на каждом кадре. Ширина не должна
  прыгать при переключении вкладок.
- Спящая вкладка: план читается из файла, панель работает. Досье выключено → плана нет, кнопки нет.
- Прораб и исполнители: у каждого свой план, сводного нет.
- Уживание с другими панелями: ⌘J терминал снизу — план на всю высоту справа; терминал сбоку —
  агент | терминал | план; когда агенту остаётся < ~60 колонок, панель плана сворачивается в
  кнопку. ⌘B и верхняя раскладка карточек независимы.

## Шаги

1. **Чистый модуль** `plan.js` (dual-mode, как tabstyle.js/railmini.js): разбор раздела «## План»
   в дерево `{text, state: done|todo|now, children}` и счёт верхних шагов; «где мы». Тест
   `test/plan.test.js` (в package.json список test и toplevel.test.js FILES). Края: нет раздела,
   одна строка, кривые отступы, вложенность 3 уровня, CRLF, `[X]` заглавная.
2. **main**: при обновлении файла работы (место — рядом с dossierRefreshMark) разобрать план,
   слать окну `session:plan {id, plan|null}` (preload + контракт-тест preload-contract); окно
   ничего в файл не пишет. «Открыть файл работы» — уже есть путь (dossierEnsure / shell.openPath).
3. **renderer**: состояние `s.plan`; кнопка (#plan-btn в #stage-agents), панель (#plan-panel +
   разделитель, ширина в localStorage), правила 1–5 выше, автозакрытие/автооткрытие, рендер дерева
   и бейджа; отступ дайджеста справа под кнопку; refit по концу перетаскивания; стыковка с
   termpanel (⌘J) и узким окном. Горячая клавиша — на усмотрение, добавить в keybinds RESERVED
   если берёшь (⌘B уже занят свёрткой левой панели).
4. **Подсказка агенту** (hooks/swarm-signal.mjs dossierNote): отметки строго `[ ]`/`[x]`/`[>]`
   в начале пункта, верхний уровень — шаги, которые видит человек; формат уже почти такой —
   только уточнить и покрыть тестом хука (test/hook.test.js).
5. **Стенд**: снять кадры продакшн-CSS (кнопка с дайджестом и без, панель открыта, вкладка без
   плана, ⌘J сбоку/снизу, узкое окно, ⌘B) — сравнить с макетом; рецепт и грабли — docs/img/README.md.
6. **Доки**: строка в CHANGELOG (Unreleased), раздел в MANUAL.md (стиль user-docs-style: по флоу
   человека, мышью, живым русским, без внутренностей; рядом с «Досье вкладки»), README при

## Как проверять и чего не трогать

- `npm test` целиком; стенд — скрытое окно электрона, свой userData; payload/ и работающий сворм
  не трогать, приложение не перезапускать (memory local-payload-delivery, session-runs-inside-the-app).
- Коммитить только свои файлы явными путями (в дереве работают соседи; memory concurrent-agents).
- Имена файлов — латиницей. Релиз не делать.
