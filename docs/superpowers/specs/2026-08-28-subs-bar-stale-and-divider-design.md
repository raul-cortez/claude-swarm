# Боттомбар подписок: разделитель между подписками и «—» вместо протухшего числа

28 августа 2026. Обсуждение с владельцем: одна из подписок исчерпала недельный лимит, и с того
момента панель показывает застывшие числа как будто актуальные — расход не различить от текущего
на глаз. Заодно попросили разделитель между подписками в самой панели: сейчас они слипаются в
одну ленту.

## Зачем

`subs.js pills()`/`previewPills()`/`menuRows()` строят пилюли из последнего снимка расхода
(`main.js subsAccounts()`, раз в 20 секунд). Если по аккаунту перестали запускаться агенты (типичная
причина — исчерпан недельный лимит, дальше на этой подписке просто не работают), новые снимки
перестают приходить, а последний известный процент так и висит в панели без пометки — до следующего
реального ответа модели на этом аккаунте панель обманывает: показывает число как текущее, хотя оно
может быть давно неверным.

Разбор `subs.js windowRow()` (строки 237–253) показал: точный признак «число точно устарело» уже
есть в данных, ничего изобретать не нужно. Каждое окно несёт `resetsAt` — момент, когда именно оно
должно обнулиться. Если `now > resetsAt`, окно уже должно было сброситься, а свежего снимка так и не
пришло — значит показанный процент гарантированно неверен (реальный неизвестен, а не «примерно
такой же»). Это не эвристика по времени последнего снимка (агент мог просто не отвечать 10 минут,
число при этом всё ещё верно — раз никто не работал, расход не менялся) — а точный факт по каждому
окну отдельно. Поэтому новый порог/константа не нужны.

Заодно нашёлся маленький существующий баг рядом: `fmtResetWhen()` для окна, чей срок сброса уже
прошёл, сегодня говорит «обновится через минуту» (`fmtRel()` зажимает отрицательные секунды в 0,
строка 211) — то самое ложное «вот-вот» для окна, которое на самом деле зависло. Правится тем же
диффом.

## Дизайн

### 1. `subs.js windowRow()` — признак `stale`

```
stale: resets > 0 && resets <= nowSec
```

Когда `stale`, `level` форсируется в `''` вместо вычисленного по `spent`: устаревшее число не
должно красить пилюлю в `tight`/`crit` борде́ром — текущий уровень неизвестен, врать бордюром так
же плохо, как цифрой. `worstLevel()` не меняется — она уже просто берёт худший `level` из списка
окон, а протухшее окно теперь само приходит с `level: ''`.

`eta` для протухшего окна и так не считается: `left = resets > nowSec ? resets - nowSec : 0`,
`wantEta && left` — при `left === 0` условие ложно. Менять не нужно.

### 2. `fmtResetWhen()` / текст «когда обновится» — без ложного «через минуту»

Новая функция в `subs.js`, рядом с `fmtResetWhen()`: `fmtStaleSince(resetsAtMs, nowMs)` — то же
форматирование, что `fmtWhen`/`fmtRel` (сутки — точным временем, меньше суток — отсчётом), но про
момент в ПРОШЛОМ: «должно было обновиться `<когда>`». Единственный вызывающий — `menuRows()` (строки
418–421): когда `five.stale`/`seven.stale`, поле `when.five`/`when.seven` заполняется результатом
`fmtStaleSince()` вместо `fmtResetWhen()` (которая для просроченного `resetsAt` и так уходила в
«через минуту» — саму `fmtResetWhen`/`fmtRel` не трогаем, просто на неё для этого случая больше не
ходят). `pillTitle()` и `fillSubsMenu()` берут готовую строку из `row.when[w]` как и раньше — они уже
не знают, откуда она взялась, различие целиком внутри `menuRows()`.

`pillTitle()` (renderer.js) для `it.stale` меняет саму фразу вокруг числа: не «61% (обновится
`<when>`)», а «— (`<when>`, новых чисел нет)» — `<when>` тут уже строка из `row.when[w]`, которая для
протухшего окна и так пришла в прошедшем времени.

### 3. Пилюля в боттомбаре — `renderer.js pillNode()` + `styles.css`

Для `it.stale`: `.u-num` печатает `—` вместо `${it.spent}%`, получает класс `stale` (приглушённый
цвет, не `tight`/`crit`). `.u-lab` (`5ч`/`7д`) остаётся как есть, чуть приглушается вместе с числом.
Остальные окна той же пилюли (если не протухли) рендерятся как сейчас — приглушение точечное, не на
всю пилюлю: пример из мокапа — «5ч: —», «7д: 100%» в одной и той же пилюле подписки, у которой
истёк недельный лимит, но 7-дневное окно ещё честно ждёт своего срока.

`pillTitle()` — для протухшего окна в подсказке та же фраза из п.2 вместо «5 часов: 61% (обновится
через минуту)».

### 4. Разделитель между подписками — `#usage-pills` + `styles.css`

Между `.usage-pill`-кнопками (не между окнами внутри одной пилюли — это по-прежнему `·`) —
новый пустой `<span class="u-divider">`, вставляется в `renderUsagePills()` между
`appendChild(pillNode(...))` для соседних строк. `border-left` НА самой пилюле не подходит: у
`.usage-pill` есть `border-radius: 6px`, и одиночная граница на скруглённом углу визуально гнётся
(проверено на мокапе — выглядит как скобка). Разделитель — отдельный `1px`-элемент, растянутый по
высоте ряда (`align-self: stretch`), цвет — `var(--border)`.

### 5. Список по клику — `renderer.js fillSubsMenu()` / `menuRows()`

Та же логика, что в пилюле: `—` вместо числа для протухшего окна (в `.u-win .u-num`), и то же
«должно было обновиться…» вместо счётчика в поле `when` (п.2) — решили не оставлять там последнее
известное число с пояснением, а вести себя одинаково с панелью: меньше двух разных языков для одного
и того же факта.

### Не меняется

- `main.js subsAccounts()`, частота снимков (20 с) — источник данных не трогаем, вопрос ровно в
  том, как честно показать то, что из него уже приходит.
- Само правило «нет окна в снимке → пилюли/строки нет» (`windowRow()` возвращает `null` на
  `spent == null`) — это другой случай («не пришли числа вообще»), не про протухшее.

## Тестирование

`test/subs.test.js` — новые кейсы на `windowRow()`: `stale: true`/`level: ''` когда `resetsAt` в
прошлом и есть снимок, `stale: false` когда `resetsAt` в будущем; `fmtStaleSince()` не выдаёт
«через минуту» для просроченного окна, а называет момент в прошлом; `menuRows()` подставляет
`fmtStaleSince()` в `when.five`/`when.seven` вместо `fmtResetWhen()` ровно когда окно `stale`.
`test/hook.test.js` не затрагивается — признак `stale` не идёт в текст хука, это чисто UI-панели.

Ручная проверка после правки (у автора уже есть подписка с протухшим окном — см. контекст) —
свежая сборка `npm run dist` или обычный `npm start`, посмотреть боттомбар и список по клику.

`subs.js` (`windowRow()`, новая `fmtStaleSince()`, `menuRows()`), `renderer/renderer.js`
